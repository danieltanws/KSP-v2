# LION — retained gaps

**Levers, Innovations, Opportunities and Nexus.** Where a gap goes once it is
worth keeping.

```
unapproved/   produced by a skill, not yet reviewed by a person
approved/     a person read it and signed it off
```

**The folder is the state.** A gap is approved by moving its file from one
folder to the other. There is no status column and no index to keep in step —
`git log` already records who moved what, and when.

## What lives here

One markdown file per gap, in the six-section shape from
`docs/LION_Output_Template.md`: evidence base, problem side, response side, the
gap, what is missing, what would change this.

Name it `YYYY-MM-DD-theme-geography-slug.md` so the folder sorts by date.

## Nothing lands here automatically

A skill run does not write a file. Gaps arrive here because someone asked for
one to be kept — which is what makes the contents a deliberate record rather
than a log of every question anyone tried.

**And asking is not the last step.** Show the filename and the six sections,
and wait for a yes before writing. A gap is an argument assembled from inferred
classifications; what gets kept should be the version the person actually read,
not the one produced a moment earlier.

## Two things to hold on to

**`unapproved/` is the normal state.** Most gaps are coverage artefacts — they
reflect what has been read, not what is true of the world. A low approval rate
is the system working, not failing.

**Approval is not a finding becoming a fact.** It means a person who knows the
field read the gap and thought it worth carrying forward. The evidence base at
the top of the file says what it still rests on, and that does not change by
moving folder.
